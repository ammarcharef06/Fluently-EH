# H2b — Windows EXE + Authenticode

**الحالة: مؤجل بقرار، وليس فشلًا.**  
**تاريخ القرار:** 2026-11-01.  
**إعادة التقييم:** قبل اعتماد إطلاق Windows، وليس بتمديد H2a.

## السؤال المؤجل

هل يمكن بناء تطبيق Tauri/Windows وتضمين حزمة المنهج والتحقق منها وقت التشغيل، ثم إنتاج EXE/installer موقّع بشهادة Authenticode موثوقة ضمن شروط توزيع المشروع؟

## سبب التأجيل

- بيئة التنفيذ الحالية لا تحتوي Rust/Tauri toolchain مثبتًا أو مُثبت التوافق.
- لا توجد شهادة Authenticode موثوقة أو خدمة توقيع معتمدة متاحة للشاهد.
- نجاح H2a على Android لا يقدم دليلًا على Windows أو EXE.
- لا نريد استخدام توقيع ذاتي أو ملف غير موقع ثم وصفه بأنه قابل للنشر الموثوق.

## صياغة الحالة المعتمدة

**غير مُثبت — خارج نطاق المرحلة 1 بسبب غياب Rust/Tauri والتوقيع.** لا يوصف ذلك بأنه فشل تقني؛ لم يُجر اختبار H2b أصلًا.

## ما يلزم لإعادة فتحه

1. Runner Windows نظيف مع إصدارات Rust وCargo وTauri وNode وWebView2 موثقة.
2. اختبار build/install/launch مستقل.
3. حزمة منهج اختبار حقيقية الشكل مضمّنة داخل EXE/installer وقراءة runtime منها.
4. اختبار تحقق ورفض payload معدل ضمن ملف التوزيع نفسه.
5. مسار Authenticode موثق، مع تحديد هل الشهادة مدفوعة/موجودة وكيفية حفظ المفتاح خارج المستودع.
6. قياس حجم الملف ووقت البناء والتثبيت/الإطلاق.
7. قرار ADR جديد قبل إضافة H2b إلى نطاق تنفيذ نشط.

لا يُستنتج من ذلك أن Windows سيُلغى أو أن EXE غير ممكن؛ فقط أن الدليل غير متوفر في هذه المرحلة.
