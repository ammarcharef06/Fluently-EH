# H2b — Windows EXE + Authenticode

**الحالة: مؤجل بقرار، وليس فشلًا.**  
**تاريخ القرار:** 2026-11-01.  
**إعادة التقييم:** قبل اعتماد إطلاق Windows، وليس بتمديد H2a.

## السؤال المؤجل

هل يمكن بناء تطبيق Tauri/Windows وتضمين حزمة المنهج والتحقق منها وقت التشغيل، ثم إنتاج EXE/installer موقّع بشهادة Authenticode موثوقة ضمن شروط توزيع المشروع؟

## سبب التأجيل

- بيئة التنفيذ الحالية لا تحتوي Rust/Tauri toolchain مثبتًا أو مُثبت التوافق.
- لا توجد شهادة Authenticode موثوقة أو خدمة توقيع معتمدة متاحة للشاهد.
- نجاح H2a على Android لا يقدم دليلًا على Windows أو EXE.
- لا نريد استخدام توقيع ذاتي أو ملف غير موقع ثم وصفه بأنه قابل للنشر الموثوق.

## صياغة الحالة المعتمدة

**غير مُثبت — خارج نطاق المرحلة 1 بسبب غياب Rust/Tauri والتوقيع.** لا يوصف ذلك بأنه فشل تقني؛ لم يُجر اختبار H2b أصلًا.

## شروط إعادة فتح H2b الثلاثة — يجب تحققها جميعًا

1. **بيئة Windows قابلة للتكرار:** توفر Windows runner نظيف ومثبت الإصدار، مع Rust/Cargo وTauri وNode وWebView2 بإصدارات موثقة، وصلاحية بناء وتثبيت وتشغيل artifact على Windows حقيقي أو VM مدعوم.
2. **مسار تقني قابل للإثبات:** نجاح بناء EXE/installer وتضمين payload اختبار، وقراءة التطبيق له من داخل التوزيع، ثم اختبار checksum سليم/معدل ورفض التفعيل عند تغيير بايت واحد، مع قياس الحجم وزمن البناء والتثبيت/الإطلاق. لا يكفي نجاح build وحده.
3. **توقيع Authenticode موثوق ومصرح به:** توفر شهادة Authenticode صالحة وسلسلة ثقة قابلة للتحقق، مع حسم تكلفة الشهادة وتجديدها وقبولها ضمن ميزانية المشروع، وتخزين المفتاح/خدمة التوقيع خارج المستودع. إذا لم يتوفر ذلك، يبقى H2b مؤجلًا؛ لا يوصف توقيع ذاتي أو ملف unsigned بأنه اجتاز شرط Authenticode.

بعد تحقق الشروط الثلاثة، يُفتح ADR وملف شاهد H2b جديد أو تحديث لهذا الملف قبل كتابة أي كود أو تشغيل CI. لا يؤدي تحقق شرطين من ثلاثة إلى إعادة فتح جزئية؛ يسجل الوضع كـ "مؤجل بقرار".

لا يُستنتج من ذلك أن Windows سيُلغى أو أن EXE غير ممكن؛ فقط أن الدليل غير متوفر في هذه المرحلة.
