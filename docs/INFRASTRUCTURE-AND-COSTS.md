# البنية التحتية والتكاليف — Fluently

## 1. الهدف والقيود
يجب أن يكون Fluently مجانيًا للمتعلمين، دون إعلانات أو اشتراكات أو فترات تجريبية. يسعى المشروع إلى تشغيل البنية بخدمات مجانية مستمرة أو استضافة ذاتية، لكن لا يُفترض أن الخدمات المجانية غير محدودة أو مضمونة إلى الأبد.

## 2. التكوين المستهدف مبدئيًا

| الوظيفة | المرشح |
|---|---|
| واجهة الويب والملفات الثابتة | Cloudflare Pages/Workers Static Assets حسب الاختبار |
| API | Hono + TypeScript على Cloudflare Workers |
| PostgreSQL | Neon Free |
| اتصال PostgreSQL | Cloudflare Hyperdrive عند ملاءمته |
| ملفات المنهج والصوتيات | واجهة تخزين مستقلة؛ Neon Object Storage مرشح أولي، وR2 بديل بعد التحقق من شروط الفوترة |
| نطاق أولي | نطاق مجاني تابع لمنصة الاستضافة |
| بريد التحقق والاستعادة | لم يُحسم |
| توليد الصوت | محرك مفتوح المصدر محلي/ذاتي الاستضافة بعد فحص الرخص والجودة |

## 3. الحصص التي يجب مراقبتها
الأرقام التالية لقطة تخطيطية من الوثائق العامة التي تمت مراجعتها في 1 نوفمبر 2026؛ يجب إعادة التحقق منها في يوم الإنشاء والنشر، ولا تمثل ضمانًا تعاقديًا.

### Cloudflare Workers Free
- حد منشور: 100,000 طلب يوميًا.
- 10ms CPU لكل طلب.
- 128MB ذاكرة.
- 50 subrequests لكل طلب.
- عدد وحدات/ملفات وأحجام نشر محدودة حسب الخطة.

المصدر: https://developers.cloudflare.com/workers/platform/limits/

### Neon Free
- 100 مشروع.
- 10 فروع لكل مشروع.
- 100 CU-hour لكل مشروع شهريًا.
- 1GB تخزين PostgreSQL لكل مشروع، وحد تجميعي للحساب حسب الخطة.
- 5GB نقل شبكة عام لكل مشروع شهريًا.
- التوسع إلى السكون بعد فترة خمول حسب إعداد الخطة.

المصدر: https://neon.com/docs/introduction/plans

### Neon Object Storage
- أُعلن عن حصة 5GB لكل مشروع في الخطة المجانية في أكتوبر 2026 بحسب وثائق/إعلانات Neon.
- يجب التحقق من شرط البطاقة وطريقة تفعيل الخدمة وحدود العمليات والنقل وشروط الإيقاف قبل اعتمادها.

المصدر: https://neon.com/blog/neon-free-plan-1-gb-per-project

### Cloudflare R2
- توجد حصة تخزين وعمليات مجانية معلنة.
- قد يتطلب إعداد الفوترة أو Checkout.
- لا يُعتمد ضمن شرط المشروع قبل إثبات إمكانية استخدامه دون بطاقة ودون تفعيل فوترة غير مقصودة.

المصدر: https://developers.cloudflare.com/r2/pricing/

## 4. سياسة عدم الرسوم
قبل اعتماد أي مزود:
1. فحص صفحة الأسعار الرسمية وشروط الخطة المجانية.
2. التحقق من أن الخطة ليست فترة تجريبية محددة.
3. التحقق من التسجيل دون بطاقة إذا كان هذا شرطًا مطلوبًا.
4. التحقق من عدم وجود فوترة تلقائية أو رسوم تجاوز.
5. تحديد حدود الحساب والمشروع والطلب والتخزين والنقل.
6. اختبار ما يحدث عند استنفاد الحصة.
7. تعطيل أو منع أي ترقية مدفوعة تلقائية.
8. توثيق تاريخ التحقق وروابط المصدر.
9. توفير بديل قابل للنقل.
10. لا يُدخل أي مفتاح أو بيانات دفع في المستودع.

إذا لم يوجد مزود يفي بالشروط، لا نخفي التكلفة؛ نؤجل الوظيفة المركزية أو نستخدم استضافة ذاتية يملكها المشروع، مع بيان تكلفة الكهرباء والاتصال والصيانة إن وجدت.

## 5. مراقبة الحصص
تحتاج الإدارة إلى لوحة داخلية تعرض:
- عدد طلبات Workers والاستهلاك.
- CPU لكل مسار.
- استخدام قاعدة البيانات والتخزين.
- compute-hours.
- النقل الشبكي.
- التخزين الكائني وعمليات القراءة/الكتابة.
- أحجام الحزم والتنزيلات.
- رسائل البريد المرسلة.
- أخطاء 429 و5xx وحدود الخدمة.

عند الاقتراب من الحد:
- يصدر تنبيه للمسؤول.
- تُخفض المهام غير الضرورية.
- تُمنع عمليات رفع/تحويل كثيفة غير ضرورية.
- لا تُفعّل خطة مدفوعة تلقائيًا.
- لا يتوقف العمل المحلي للمتعلم.

## 6. تقدير تكلفة يجب إنجازه قبل الإنتاج
يجب إنشاء نموذج تقدير يستخدم:
- عدد الحسابات النشطة شهريًا.
- متوسط دروس/طلبات المستخدم.
- متوسط حجم حزمة المنهج.
- نسبة تنزيل الصوتين.
- مرات تحديث المحتوى.
- حجم سجل التقدم.
- معدل مزامنة الأجهزة.
- عدد بلاغات الدعم.
- وقت تشغيل الخادم.
- عدد عمليات تخزين الملفات.

لا تُخترع تكلفة شهرية قبل قياس أحجام المحتوى والاستخدام. تُسجل التكاليف الفعلية أو الحصص المستهلكة في تقرير التبرعات عند تفعيلها.

## 7. سياسة تخزين الملفات
يوفر التطبيق واجهة موحدة لتخزين:
- حزم ZIP.
- ملفات الصوت.
- الصور.
- manifest والإصدارات.
- ملفات التحديث.

المتطلبات:
- رفع وتنزيل قابل للاستئناف عند دعم المزود.
- معرفات ملفات مستقرة.
- بصمات وسلامة.
- عدم ربط المحتوى برابط مزود دائم في بيانات المنهج.
- إمكانية نسخ الملفات ونقلها إلى مزود آخر.
- منع نشر ملف قبل اكتمال رفعه والتحقق منه.
- عدم وضع بيانات متعلم في حزم عامة.

## 8. توليد الصوت
- محرك TTS مفتوح المصدر يُختار بعد اختبار أصوات أمريكية رجالية ونسائية.
- توليد مسبق داخل بيئة إعداد المحتوى، لا في كل جلسة تعلم.
- لا تعتمد عملية التوليد على API مدفوعة أو رصيد تجربة.
- تُراجع شروط توزيع الأصوات والنماذج والبيانات المرافقة.
- تحفظ النص وإصدار المحرك وإعداداته.
- فحوص آلية ومراجعة بشرية قبل النشر.
- لا تقييم صوتي للمتعلم.

## 9. البريد والمصادقة
إرسال التحقق واستعادة الحساب وظيفة لازمة. لم يُعتمد مزود بريد بعد. يجب فحص:
- الخطة المجانية المستمرة.
- هل يلزم بطاقة؟
- الحد اليومي والشهري.
- قيود النطاق والإرسال الجماعي.
- قابلية تسليم الرسائل.
- حماية إساءة الاستخدام.
- شروط الاحتفاظ بالبيانات.

إذا لم تتوفر خدمة مناسبة بلا رسوم أو تجربة، يجب التصريح بذلك واختيار مزود ذاتي الاستضافة إن كان ممكنًا عمليًا، أو تأجيل المزامنة التي تتطلب البريد، وليس الادعاء بأن البريد مجاني.

## 10. استضافة ذاتية بديلة
يجب أن يمكن تشغيل:
- Hono API في بيئة Node.js أو متوافقة.
- PostgreSQL قياسي.
- تخزين ملفات متوافق مع S3 أو واجهة بديلة.
- بريد SMTP يملكه المشروع.
- ملفات حزم ثابتة عبر CDN أو خادم ملفات.

لا يعني ذلك أن الاستضافة الذاتية مجانية بالكامل؛ هناك تكاليف جهاز وطاقة واتصال ونطاق وصيانة.

## 11. التبرعات
- اختيارية ولا تمنح ميزات أو محتوى إضافيًا.
- تُعرض المصروفات الفعلية أو الحصص والتكاليف بوضوح.
- لا تُفعّل وسيلة تبرع قبل مراجعة شروطها وتوافقها مع رخصة المحتوى والقانون.
- لا تُستخدم التبرعات لتبرير رسوم تلقائية أو اشتراكات خفية.

## 12. بوابة اعتماد مزود
لا يدخل أي مزود إلى الإنتاج إلا بعد:
- اختبار فعلي.
- مراجعة السعر والشروط.
- مراجعة البطاقة والفوترة.
- اختبار حد الاستخدام.
- اختبار التوقف والاستعادة.
- اختبار التصدير والنقل.
- توثيق قرار الاعتماد في DECISIONS.md.
