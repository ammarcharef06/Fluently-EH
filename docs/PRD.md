# وثيقة متطلبات المنتج (PRD) — Fluently

- الحالة: مواصفات تأسيسية معتمدة مبدئيًا.
- المنتج: Fluently.
- الجمهور: الناطقون بالعربية.
- اللغة المستهدفة: الإنجليزية الأمريكية.
- معيار مستويات الكفاءة: CEFR من Pre-A1 إلى C2.
- ملاحظة: هذه الوثيقة تصف المتطلبات المقصودة، ولا تعني أن الوظائف قد نُفذت.

## 1. ملخص المنتج

Fluently منصة مجانية متعددة المنصات لتعليم الإنجليزية من محو الأمية إلى الطلاقة المتقدمة. تجمع المنهج المنظم، والتمارين، والاختبارات، والمراجعة المتباعدة، ولوحة تقدم، ومحرر محتوى إداريًا. بعد أول تسجيل دخول وتوفر حزمة المنهج محليًا (تنزيل أولي على الويب، أو نسخة مضمّنة في تثبيت Android وWindows)، يجب أن تستمر الوظائف التعليمية الأساسية دون اتصال، ثم تزامن النتائج عند عودة الاتصال.

## 2. أهداف المنتج

1. تمكين شخص لا يعرف الحروف الإنجليزية من بدء التعلم.
2. توفير مسار واضح ومتدرج حتى C2.
3. تدريس الإنجليزية الأمريكية مع شرح عربي فصيح مبسط.
4. قياس القراءة والكتابة والاستماع والتحدث والقواعد والمفردات بحسب المرحلة.
5. قياس الإتقان من خلال أسئلة جديدة ومحاولات متعددة وتطبيق عملي.
6. تقديم خطة علاجية عند التعثر.
7. تمكين التعلم دون اتصال بعد التنزيل الأول.
8. إدارة المحتوى وإصداراته دون الحاجة إلى إعادة بناء التطبيق لكل تعديل تعليمي.
9. الحفاظ على مجانية المتعلم وعدم الاعتماد على خدمات تجريبية أو رسوم غير مقصودة.

## 3. المستخدمون والأدوار

### 3.1 المتعلم
- يسجل الدخول عبر Google أو البريد وكلمة المرور.
- يؤكد البريد عند استخدام البريد وكلمة المرور قبل المزامنة.
- يختار البدء من الصفر أو اختبار تحديد المستوى.
- يحصل على اسم مستعار؛ المعلومات الأخرى اختيارية.
- يملك ملف تعلم محليًا وسحابيًا بحسب إعدادات المزامنة.
- يمكنه تصدير بياناته وطلب حذف حسابه وبياناته.

### 3.2 أدوار الإدارة
- المدير الرئيسي: إدارة النظام والموظفين.
- محرر المحتوى: إنشاء المحتوى وتعديله.
- المراجع: فحص المحتوى وإضافة الملاحظات واعتماده ضمن صلاحياته.
- مسؤول النشر: إصدار حزم المحتوى وإدارة نشرها والتراجع عنها.

ينشئ المدير الرئيسي حسابات الموظفين ويرسل الدعوات. تُطبق الصلاحيات على الخادم.

## 4. المنصات

| المنصة | المتطلبات |
|---|---|
| الويب | React + TypeScript + PWA، مع تنزيل المنهج كاملًا عند أول استخدام |
| Android | تطبيق Capacitor وتوزيع APK مجاني مباشر |
| Windows | تطبيق Tauri وتوزيع EXE عبر الموقع وإصدارات GitHub |

واجهة واحدة متجاوبة؛ تتكيف عناصر التنقل مع الهاتف والكمبيوتر. دعم الأجهزة المتوسطة والحديثة، مع توثيق الحدود الدنيا للأجهزة الضعيفة بعد الاختبار.

### 4.1 متطلبات كل منصة
التفاصيل التنفيذية للأذونات والتخزين المؤقت ودورة حياة التطبيق والتحديثات والتوقيع وتكاملات النظام ومعايير قبول كل منصة موثقة في [متطلبات المنصات](PLATFORM-REQUIREMENTS.md). هذه الوثيقة مكملة لمصفوفة التتبع ولا تُعد إثباتًا للتنفيذ.

- **Web/PWA:** ينزل حزمة المنهج كاملة بعد أول تسجيل دخول؛ يستخدم Service Worker وCache Storage لهيكل التطبيق والملفات الثابتة، وIndexedDB لبيانات التعلم. يجب إظهار حدود المساحة واحتمال إخلاء تخزين المتصفح وعدم ضمان بقائه الأبدي.
- **Android:** تُحفظ بيانات التعلم في SQLite وملفات التطبيق الخاصة. تُطلب أقل الأذونات اللازمة، ولا يُطلب إذن الميكروفون. تُوزع تحديثات APK بتوقيع ثابت، ويؤكد المستخدم التثبيت عبر النظام.
- **Windows:** تُحفظ بيانات التعلم في SQLite ومجلد بيانات المستخدم، لا في مجلد التثبيت. تكون الاتصالات صادرة عبر HTTPS دون فتح منافذ واردة. تُحفظ سلامة البيانات عند الترقية، ويُوضح أن ملفات QA الحالية غير موقعة. لا يعد Authenticode متطلبًا للاستخدام الخاص الحالي؛ فحوص سلامة المنهج الموجودة في H2b-4 تبقى كما هي.
- **لوحة الإدارة:** تطبيق ويب مستقل منطقيًا عن تطبيق المتعلم، مع إعادة استخدام الحزم المشتركة وتفويض جميع العمليات على الخادم.

## 5. تجربة المستخدم

- واجهة عربية وإنجليزية مع إمكانية التبديل.
- العربية الفصحى المبسطة لغة شرح أساسية.
- الإنجليزية الأمريكية لغة التعلم المستهدفة.
- سمة فاتحة وداكنة وتلقائية حسب الجهاز.
- لوحة رئيسية تعرض التقدم والخطة والمراجعات والإنجازات بشكل مختصر.
- زر واضح لمتابعة آخر درس.
- دروس قصيرة مستهدفة من 10 إلى 15 دقيقة.
- خطوات متتابعة داخل الدرس مع إمكانية الرجوع.
- إعدادات صوت مستقلة للتشغيل التلقائي واليدوي ومستوى الصوت والتكرار.
- تذكيرات اختيارية قابلة للإيقاف.
- إعدادات وصول أساسية قابلة للتوسع.
- لا إعلانات، ولا تنافس، ولا لوحات ترتيب.

## 6. بنية المنهج

الهيكل المنطقي:
مسار تعليمي ← مرحلة تأسيسية أو مستوى CEFR ← وحدة ← درس ← نشاط ← تمرين/اختبار.

### 6.1 المستويات
- مرحلة محو الأمية قبل A1.
- Pre-A1.
- A1.
- A2.
- B1.
- B2.
- C1.
- C2.

كل مستوى يُقسّم داخليًا إلى مراحل ووحدات ودروس وأهداف إتقان.

### 6.2 المسارات
- مسار رئيسي شامل.
- مسارات فرعية اختيارية مثل الإنجليزية الأكاديمية والمهنية والمحادثة والتحضير لاختبارات خارجية. لا تُعد هذه المسارات شهادات أو اختبارات معتمدة يصدرها Fluently.

### 6.3 مرحلة محو الأمية
تغطي:
- الحروف الكبيرة والصغيرة معًا.
- أسماء الحروف وأصواتها.
- الصوتيات ودمج الأصوات.
- قراءة وتهجئة الكلمات.
- الكتابة عبر لوحة المفاتيح.
- الجمل الأولى وعلامات الترقيم.
- الأنماط المنتظمة أولًا والاستثناءات تدريجيًا.

### 6.4 المهارات
تُطور القراءة والكتابة أولًا، مع إدخال الاستماع والتحدث والنطق تدريجيًا قبل A1. تشمل المنظومة القواعد والمفردات والعبارات الواقعية وفهم السياق والتعبير. تختلف مكونات الدرس حسب هدفه.

لا تُستخدم رموز IPA في أي جزء من المنتج. يمكن استخدام كتابة عربية تقريبية في مرحلة البداية فقط، ثم الاستغناء عنها تدريجيًا.

## 7. مواصفات المحتوى التعليمي

- القواعد: شرح مستقل لكل قاعدة، ثم تطبيقها داخل الجمل والمواقف؛ يشمل الشرح الاستخدام والاستثناءات والأخطاء الشائعة.
- المفردات: أهداف لكل وحدة ومستوى، مع قياس الكلمات النشطة. الأولوية للعبارات والجمل الواقعية، مع معنى سياقي ونطق أمريكي وأمثلة واستخدامات شائعة.
- المحتوى: أمثلة، حوارات، قصص متدرجة، مقالات، رسائل، نصوص واقعية وأكاديمية ومهنية.
- الحروف المركبة: تدريس تدريجي.
- الاستثناءات: بعد فهم الأنماط المنتظمة.
- النطق: تسجيلات مولدة مسبقًا بصوت أمريكي رجالي ونسائي، مع فحوص آلية ومراجعة بشرية قبل النشر.
- مكتبة الصوت: مكتبة مشتركة للأصوات والكلمات المتكررة، وصوتيات خاصة للحوارات والقصص والدروس.

## 8. هيكل الدرس

يتغير حسب نوع الدرس، وقد يتضمن:
- هدفًا تعليميًا واضحًا.
- شرحًا عربيًا مبسطًا.
- أمثلة إنجليزية.
- صوتًا أو قراءة عند الحاجة.
- تمارين متدرجة.
- تطبيقًا في سياق جديد.
- اختبارًا قصيرًا.
- تصحيحًا فوريًا يشرح السبب.
- تمرينًا علاجيًا.
- إضافة العناصر المناسبة إلى المراجعة المتباعدة.

## 9. التمارين وبنك الأسئلة

أنواع التمارين تشمل الاختيار، والترتيب، والتوصيل، والكتابة، والترجمة، والقراءة، والاستماع، والتهجئة، والمواقف الواقعية.

يجب أن:
- تُخزن الأسئلة ضمن حزم المنهج وتُدار عبر بنك أسئلة مركزي.
- تُصنّف حسب المستوى والمهارة والصعوبة والموضوع والهدف.
- تُدعم إعادة الاستخدام وبناء الاختبارات من البنك.
- تتغير صياغة السؤال وسياقه في الاختبارات الجديدة، لاختبار الفهم لا الحفظ.
- تتوفر تلميحات تدريجية دون كشف الحل مباشرة.
- يُعرض تفسير الإجابة الخاطئة ثم مثال جديد وتمرين علاجي.
- تُحفظ أسئلة الذكاء الاصطناعي المقترحة كمسودات، ولا تُنشر تلقائيًا.

## 10. تحديد المستوى والتقييم

- يستطيع المتعلم البدء من الصفر أو إجراء اختبار تحديد مستوى.
- تُعرض درجة عامة ودرجات مستقلة لكل مهارة.
- تُبنى قرارات الإتقان على محاولات متعددة وأسئلة جديدة وتطبيق.
- اختبارات المستوى موحدة وفق مخطط معتمد، مع أسئلة تشخيصية إضافية.
- تختلف حدود النجاح حسب نوع الاختبار والمهارة.
- عند إعادة الاختبار، تُستخدم أسئلة جديدة مع التركيز على نقاط الضعف.
- يسمح بتجاوز محتوى يثبت المتعلم إتقانه باختبار تشخيصي.
- لا يُفتح المستوى التالي إلا بعد إنهاء المتطلبات واجتياز الاختبار وإثبات إتقان المهارات الأساسية.
- لا يُقيّم النظام صوت المتعلم آليًا، ولا يسجل صوته بغرض منح درجة للنطق.

## 11. الأخطاء والمراجعة المتباعدة

- تصحيح فوري مع توضيح السبب.
- تحديد نمط الخطأ وتقديم مثال مشابه ثم تمرين جديد.
- خطة علاجية شخصية عند الإخفاق.
- جدولة مراجعة متباعدة حسب أداء المتعلم وصعوبة المعلومة وسجل تذكرها.
- خطة عودة تدريجية بعد الانقطاع دون خصم نقاط.
- خطة يومية ذكية قابلة لتعديل الوقت والوتيرة.

## 12. التقدم والتحفيز

- نقاط تكافئ الإتقان والتحسن والمراجعة والتعلم المستمر؛ لا تكافئ السرعة وحدها.
- شارات وإنجازات وتقارير تقدم.
- لا شهادات غير معتمدة.
- لا منافسة بين المستخدمين.
- لا يخسر المتعلم نقاطه بسبب الانقطاع.

## 13. العمل دون اتصال والمزامنة

### 13.1 الدخول الأول
يتطلب اتصالًا بالإنترنت لأول تسجيل دخول والتحقق من الحساب. في Web/PWA تُنزّل حزمة المنهج كاملة عند أول استخدام؛ وفي Android وWindows تُفحص النسخة المضمّنة في ملف التثبيت وتُفعّل محليًا. بعد ذلك يمكن استخدام جلسة محفوظة.

### 13.2 الوظائف المحلية
- فتح الدروس والحزم المنزلة.
- تشغيل الصوتيات.
- حل الاختبارات والتمارين.
- تنفيذ المراجعة المتباعدة.
- حفظ التقدم والعمليات محليًا.
- مراجعة لوحة التقدم المحلية.

### 13.3 المزامنة
- حفظ محلي وسحابي.
- مزامنة عند الاتصال، مع إمكانية تعطيلها.
- دمج تلقائي حسب نوع البيانات.
- العمليات غير الآمنة للدمج تُحل دون فقدان صامت؛ قد تتطلب اختيارًا أو مراجعة.
- عمليات المزامنة يجب أن تكون قابلة لإعادة المحاولة دون إنشاء إجابات مكررة.
- عند توقف الخادم يستمر التعلم وتُعاد المزامنة لاحقًا.

### 13.4 حزم المحتوى
- تتضمن إصدارات Android وWindows المستقرة حزمة المنهج المنشور كاملة داخل ملف التثبيت/التوزيع، مع اختيار حزمة الصوت الأساسية عند التثبيت؛ الصوت الآخر متاح للتنزيل لاحقًا. هذا إدراج لنسخة محتوى محددة وقت بناء الإصدار، وليس ربطًا دائمًا بتحديث التطبيق.
- نسخة الويب لا تُضمّن المنهج الكامل في ملفات الويب؛ تنزله عند أول استخدام بعد تسجيل الدخول.
- حزم ZIP تحتوي JSON وMarkdown والصور والصوتيات وملف تعريف الإصدار وبيانات الحقوق والبصمات ومتطلبات توافق التطبيق.
- تحديث المنهج مستقل عن تحديث التطبيق قدر الإمكان. يمكن للتطبيق استقبال إصدار محتوى جديد دون إعادة بناء APK/EXE ما دام مخطط الحزمة ضمن النطاق المدعوم؛ أما تغيير المخطط غير المتوافق فيتطلب تحديث التطبيق أو تحويلًا موثقًا.
- حزمة التثبيت الأصلية تتضمن أحدث نسخة منشورة وقت الإصدار؛ وتظل آلية تنزيل حزم المحتوى وتحديثها مستقلة بعد التثبيت.
- تعرض شاشة التحديث رقم الإصدار والحجم والتغييرات.
- تُحفظ الإصدارات المنشورة وإمكانية التراجع، مع سياسة لحذف النسخ غير الضرورية.

## 14. المصادقة والخصوصية

- تسجيل الدخول عبر Google أو البريد وكلمة المرور.
- تأكيد Google تلقائي بحسب موثوقية مزود الهوية؛ تأكيد البريد للحسابات التي تستخدم كلمة المرور قبل المزامنة.
- استعادة كلمة المرور برابط أو رمز تحقق عبر البريد.
- يتطلب الدخول الأول اتصالًا.
- اسم مستعار، ومعلومات إضافية اختيارية.
- فئة عمرية اختيارية، وموافقة ولي الأمر عند اللزوم القانوني.
- إحصائيات تفصيلية لكل متعلم متاحة للإدارة وفق الدور.
- لا تُرسل بيانات الدروس أو الإجابات أو المعلومات الشخصية في تقارير الأعطال.
- تقارير الأعطال اختيارية.
- تصدير بيانات المتعلم وطلب حذف الحساب والبيانات والنسخ السحابية وإبطال الجلسات.
- لا يمكن ضمان حذف نسخة محلية من جهاز ظل غير متصل؛ يُسجل طلب الحذف ويُنفذ على الأجهزة عند الاتصال مجددًا.
- التخزين المحلي ليس مشفرًا بالكامل في القرار الحالي؛ تبقى كلمات المرور وأسرار الجلسات خاضعة لمتطلبات التخزين الآمن ولا يجوز حفظها كنص صريح.

## 15. لوحة الإدارة ومحرر المحتوى

### الأدوار
- مدير رئيسي.
- محررو محتوى.
- مراجعون.
- مسؤولو نشر.

### وظائف الإدارة
- إدارة كل مراحل المنهج والدروس والتمارين والأسئلة والمفردات والقواعد والصوتيات والمراجع والألعاب والإنجازات والتحديثات.
- إنشاء حسابات الموظفين بالدعوة من المدير الرئيسي.
- إحصائيات تفصيلية لكل مستخدم.
- استقبال الأخطاء والاقتراحات وتتبع حالتها.
- سجل تدقيق وإصدارات، مع استرجاع النسخ السابقة.

### المحرر
- واجهة مرئية وحقول منظمة وإمكانية تحرير متقدم.
- قوالب متعددة قابلة للإنشاء والتعديل.
- دعم النص والصور والصوت والحوارات والجداول والأمثلة والملاحظات والقواعد والمفردات والتمارين والأسئلة والمقاطع التفاعلية.
- معاينة محتوى المتعلم.
- بنك أسئلة مركزي وتصنيفات وبناء اختبارات.
- استيراد وتصدير حزم ZIP.

### المراجعة والنشر
- حالة المراجعة وملاحظاتها محفوظة مع بيانات المحتوى.
- المحتوى التعليمي لا يُنشر قبل المراجعة والاعتماد المخولين.
- فحوص آلية للهيكل والروابط والملفات والإجابات والتكرار عند توفرها.
- الصوتيات تخضع لفحوص آلية ومراجعة بشرية.
- تعديل المحتوى المنشور ينشئ إصدارًا جديدًا، يُختبر قبل النشر مع إمكانية الرجوع للقديم.

## 16. المتطلبات التقنية

### الواجهة
- React + TypeScript.
- PWA للويب.
- Capacitor لـ Android.
- Tauri لـ Windows.

### الخادم
- Hono + TypeScript على Cloudflare Workers.
- REST API موثقة عبر OpenAPI.
- Hyperdrive كخيار اتصال بـ PostgreSQL عند ملاءمته.

### البيانات
- PostgreSQL مركزيًا.
- IndexedDB للويب.
- SQLite للتطبيقات الأصلية.
- طبقة تجريد مستقلة للتخزين الكائني.

### الاستضافة
- Cloudflare Workers وNeon Free مرشحان للبداية.
- لا فترات تجريبية أو خطط تتطلب الانتقال إلى اشتراك مدفوع.
- لا تُفعّل فوترة تلقائية أو تتجاوز الحصص دون موافقة صريحة.
- يجب اختبار شروط البطاقة المصرفية والتسجيل وحدود الخطة وقت التنفيذ؛ لا تُعد الحصص المجانية ضمانًا دائمًا.

## 17. الجودة والأمان

- اختبارات وحدات وتكامل وواجهة طرفية.
- اختبارات التثبيت والتحديث والعمل دون اتصال على المنصات الثلاث.
- اختبارات المزامنة والتعارضات واستعادة البيانات.
- اختبارات الصلاحيات والأمان.
- فحص ملفات حزم المنهج قبل التثبيت أو التحديث.
- كلمات المرور تُخزن بخوارزمية مخصصة آمنة، لا كنص صريح.
- تحديد محاولات الدخول وإبطال الجلسات.
- صلاحيات الإدارة تطبق على الخادم.
- مراجعة أمنية للتغييرات الحساسة.

## 18. الإصدارات والنشر

- إصدارات مستقرة للمستخدمين فقط.
- إصدارات التطوير والاختبار داخلية.
- بناء النظام كاملًا قبل الإطلاق العام.
- نشر المراحل التعليمية تدريجيًا بعد مراجعتها.
- APK مجاني من موقع Fluently.
- EXE عبر الموقع وإصدارات GitHub.
- نطاق مجاني مبدئي، ونطاق خاص عند توفر التمويل.
- التبرعات اختيارية مع تقارير شفافة للمصروفات.
- مساهمات المجتمع عبر Pull Requests ومراجعة إلزامية.

## 19. معايير قبول المنتج قبل الإطلاق

لا يُعد الإصدار جاهزًا إلا عند:
1. نجاح بناء المنصات المستهدفة.
2. تسجيل الدخول والتحقق والاستعادة وفق الطرق المعتمدة.
3. تنزيل حزمة المنهج والتحقق من سلامتها.
4. تشغيل الدروس والتمارين والصوتيات دون اتصال.
5. حفظ التقدم محليًا واستعادته ومزامنته دون تكرار.
6. اختبار حالات التعارض وانقطاع الخادم.
7. التحقق من صلاحيات المتعلم وموظفي الإدارة.
8. اختبار حذف الحساب وإبطال الجلسات.
9. اجتياز مراجعة المحتوى وحقوق المواد.
10. اجتياز اختبارات الأداء والأمان وإمكانية الوصول.
11. إثبات أن الوظائف الأساسية لا تعتمد على خدمة مدفوعة أو فترة تجريبية.
12. توثيق حدود الأجهزة ومساحة التخزين وحصص الخدمات المجانية.
